# Security notes

Status: no external audit has been done. This file records what a self-review found and fixed, and
what is known to be weak. Treat the project as a prototype.

## Fixed in the 2026-10-16 review

| Finding | Fix |
|---|---|
| Signing in pure Python took 5.1 ms for a secret with 2 bits set and 10.1 ms for 255 set: its timing depends on the secret. The signer signs on request, so a client able to time its answers is exactly the party it must resist. | When `coincurve` is installed (`pip install 'torrenthub[fast]'`) all signing, verifying and key derivation use libsecp256k1, which is constant time and about a hundred times faster. Both backends are checked against the official BIP-340 vectors (the repo's copy is identical to bitcoin/bips master) and against each other on random, edge-case and malformed inputs. The signer reports its backend and warns when it is pure Python. The pure Python path remains the fallback. |
| A torrent received from another hub or a publisher could name any tracker or web seed, and the swarm engine would contact it. libtorrent refuses a local tracker unless its path ends in `/announce`; `http://internal-host/announce` still got a request carrying this machine's address and port. Measured, with a control. | `sanitize_torrent` keeps only the `info` dictionary, byte for byte, and adds only the operator's trackers and web seeds. It also refuses an `info` dictionary that is not in canonical form. Used for torrents fetched from hubs and for publisher torrents. |
| **The pickle scanner could not be trusted.** It read opcodes with a simplified model of the pickle machine instead of running the machine, and from reading the code I had reason to think a determined author could make it say "clean" for a file that was not. I did not build files to confirm that and did not need to. | Rewritten (`thub-scan-pickle/2`): the real unpickler runs with every import routed to one `find_class` that returns inert stand-ins and records any name off the allowlist, so the machine's own bookkeeping decides what is imported and nothing is imported or called (tested: the module a pickle names is never imported, the classes never constructed). Every pickle a loader would read is scanned: all `.pkl` entries of a zip, and up to five in a row in an older file. Refused: a zip with two entries of one name, a zip that does not start like one (loaders could read it as something else), anything unreadable, and more than 512 MiB of pickle data. Checked against real checkpoints (one legacy file and three zips from Hugging Face): all pass, no false positives. Old attestations by `thub-scan-pickle/1` should not be relied on; a replicator running the new scan will contradict a clean verdict the old one gave wrongly. |
| **Blob keys from other hubs' metadata were used to build file paths with no check.** A hash that was not hex (for example one containing `../`) made the store place blob, partial-download and torrent files outside the data directory. Verified on the path helpers; keys come from the file tables of upstream hubs, which the design treats as untrusted. | Checked three times: when metadata arrives (`files_from_info` accepts a sha256 of 64 lowercase hex digits or a git blob id of 40, a non-negative size, and a file name with no control characters, no empty, `.` or `..` parts and no leading slash), in every store path helper (`valid_key`), and at the `/blobs` and `/torrents` endpoints. Repo ids must look like `owner/name` or a bare name (`check_repo`), commit ids must be 40 hex digits, and publishing checks hashes for hex and file names for control characters. |
| File names went into the `Content-Disposition` header unencoded, so a name with a non-Latin-1 character made the download fail and a name with a quote broke the header. | An ASCII fallback name plus the RFC 5987 `filename*` form (`content_disposition`). |
| `Admission.purge()` existed but nothing called it, so quarantined events never expired in a running gateway despite the documented one-day life, and the quarantine had no overall cap. | A sweeper runs at start and every ten minutes. Strangers' events are refused with 503 when 100,000 are quarantined (`Limits.quarantine_total`); members are not affected. |
| No limit on requests per address. | A token bucket per client address on the event endpoint (burst 300, then 600 a minute) and the publish endpoint (burst 10, then 30 a minute), checked before the body is read; `THUB_EVENTS_PER_IP_BURST`, `THUB_EVENTS_PER_IP_MINUTE`, `THUB_PUBLISH_PER_IP_MINUTE` (0 turns one off). Clients that post many events (`verify-blobs`, `work`, `events-sync`) wait out a 429 using Retry-After. The address is the one uvicorn reports: behind a reverse proxy on another machine set `FORWARDED_ALLOW_IPS` to that proxy, or every client shares one bucket. |
| The event and publish endpoints read a whole request body before checking anything. A 400 MB body cost 8.3 s of CPU and hundreds of MB of memory without any credentials. | Per-endpoint body limits (`THUB_MAX_EVENT_BODY`, default 256 KiB; `THUB_PUBLISH_MAX_BODY`, default 64 MiB), enforced on the declared length and on streamed bodies. The same request is now refused in 0.33 s. Deeply nested JSON gives a clean 400. |

## Known weak, not fixed

- **Pickle files are still a risk even with the rewritten scanner** (below). Prefer safetensors. The scan says the file asks for no import outside a short tensor-rebuild list *when read by CPython's own unpickler*; a loader built on another pickle library may behave differently, and the scan says nothing about what an allowed function does with hostile arguments (for example, sizes that make a loader allocate a lot).
- The safetensors check validates structure, not content. The GGUF check is magic and version only.
- The signer protects against an agent, not against other code running as the same user, which can read the key file.
- Admission verifies a signature per event; with the Python backend that is about 20 ms. The per-address limit bounds a single address, not a distributed flood.
- A hub or relay can withhold a revocation or a newer manifest. Expiry, maximum age and asking several sources reduce this; they cannot remove it.

## Dependencies

`pip-audit` (2026-10-16) found no known vulnerabilities in `lock/runtime.txt` (36 packages, everything a deployment installs) or `lock/dev.txt`. The earlier run's only findings were against `pip` 24.0 in a development environment, since upgraded.

Versions are now bounded in `pyproject.toml` (a tested floor and the next major as ceiling) and fixed exactly in `lock/`; install with `pip install -c lock/runtime.txt ...`. The full suite passes on the locked set in a clean virtualenv. Limits: the locks hold versions, not hashes, so a tampered package index is not defended against; they were built for CPython 3.12 on Linux x86_64; and a lock goes stale: re-run the audit on a schedule (`lock/README.md` has the steps). `libtorrent` is a native library with its own history of memory-safety fixes and is the dependency most worth watching.

## Not reviewed

TLS and certificate handling (the project relies on httpx and uvicorn defaults), the MCP server's tool surface beyond what its tests cover, the libtorrent engine itself, and the container and VM images used for testing.
